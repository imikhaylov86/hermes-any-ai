# Refactor Workflow

Ты — рефакторинг-инженер. Переводи рабочий прототип из `scripts/` в модульный код в `src/`.

## Главное правило (см. AGENTS.md)

- Технические решения принимай сам, не спрашивай пользователя.
- Если рефакторинг user-facing — UI должен быть в результате (не только backend).

## Принципы

- **Не переписывай с нуля.** Извлекай логику, сохраняй проверенные решения.
- **Spec-first.** Нет спека → сначала `/architect`.
- **Инкрементально.** Один рефакторинг = одна логическая единица.

## Процесс

1. Определи что рефакторим.
2. Прочитай исходный скрипт(ы) полностью.
3. Анализ:
   - Выделенная логика → куда в `src/`
   - Переиспользуемый код (уже есть в `src/`)
   - Новые абстракции (нужно создать)
   - UI: пользователь сейчас запускает скрипт через CLI — после рефакторинга нужна страница/кнопка в `web/`
4. Прочитай `docs/SPEC_INDEX.md` и спеки.
5. Есть спек для целевого модуля? Нет → `/architect`.
6. Рефакторинг:
   - **A:** Извлечь логику → `src/`, добавить type hints, logging
   - **B:** Скрипт → тонкая CLI-обёртка (импорт из `src/`) ИЛИ удалить если фича user-facing
   - **C:** API endpoint в `src/api/routers/` для запуска
   - **D:** UI-страница/кнопка в `web/src/pages/` если user-facing
   - **E:** Тесты для извлечённой логики
   - **F:** Обновить спеки (чеклист ниже)

## Чеклист обновления спеков (обязательный)

- [ ] File tree в `docs/<domain>/overview.md` содержит новый модуль
- [ ] `SPEC_INDEX.md` описание обновлено
- [ ] `project_structure.md` обновлён если добавлен новый домен
- [ ] `__init__.py` — public функции экспортированы
- [ ] §3 UI Surface обновлён если появилась новая страница/кнопка

## Запреты

- НЕ меняй поведение при рефакторинге.
- НЕ рефактори без спека.
- НЕ удаляй старый скрипт до подтверждения что новый код работает.
- НЕ оставляй фичу CLI-only после рефакторинга — UI обязательно.

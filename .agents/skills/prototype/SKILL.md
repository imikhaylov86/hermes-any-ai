# Prototype Workflow

Скорость важнее архитектуры. Цель — проверить гипотезу.

## Когда использовать

- Нужно быстро проверить: работает ли API X? правильно ли парсится формат Y? даёт ли алгоритм Z разумный результат?
- Результат прототипа — да/нет ответ на гипотезу. Не production-код.

## Ослабленные требования (vs /implement)

- `print()` вместо logging — ок
- Хардкод путей — ок (но `.env` для API-ключей обязательно!)
- Copy-paste, нет type hints, нет тестов — ок
- UI можно пропустить (это исследование, не пользовательская фича)

## Обязательно даже в прототипе

- API-ключи из `.env`
- Файл в `scripts/_tmp/` (gitignored), не в `src/`
- Название отражает суть
- Комментарий в начале: что проверяем

## Процесс

1. Прочитай `docs/SPEC_INDEX.md` — проверь существующие модули, схемы, API клиенты.
2. Уточни в продуктовых терминах: какую гипотезу проверяем?
3. Напиши скрипт в `scripts/_tmp/`.
4. Запусти и покажи результат.
5. Спроси: будешь использовать повторно? → `/refactor` (с UI).

## Запреты

- НЕ пиши прототип в `src/`.
- НЕ импортируй из прототипов в `src/`.
- НЕ оставляй прототип как production-фичу — после подтверждения гипотезы → `/refactor` с полноценным UI.

# Review-Spec Workflow

Ты — ревьюер соответствия кода и спек проекта **Hermes Any AI**. Проверка: diff или текст спеков на соответствие чеклисту R1–R17.

## Чеклист R1–R17

- **R1** Настоящее время. Не "планируем", не история.
- **R2** Формулы и контракты. Не дампы, не логи.
- **R3** Одна формула — одно место. Остальные ссылаются.
- **R4** Структура: `§Purpose → §Features → §Decisions → §Gap`
- **R5** Размер < 50 KB. Больше → split.
- **R6** Нет TODO в теле. Нереализованное → §Gap.
- **R7** Deprecated → `Status: Deprecated → see {new_spec}` в шапке.
- **R8** Update > Create. Тема покрыта? Добавь секцию.
- **R9** ~5–7 спеков на домен.
- **R14** Change Propagation: изменился public API → обнови спеки потребителей.
- **R15** Feature spec только если: новая архитектурная подсистема ИЛИ ≥3 новых public API ИЛИ контент >200 строк.
- **R16** §Pipeline — обязательная секция каждого Overview.
- **R17** §Gap hygiene: все шаги Done → удалить §Gap. Решения → §Decisions.

## Процесс

1. Прочитай `docs/00_README.md` — реестр спеков.
2. Прочитай целевой спек полностью.
3. Если проверяешь код — сверь со спекой (структура, контракты, формулы).
4. Прогони чеклист R1–R17 по спеке.
5. Авто-фикс очевидного (R6 TODO → §Gap, R1 время глаголов) — прямо в спеке.
6. Составь отчёт: что ок, что дрейфует, что требует `/architect`.

## Запреты

- НЕ задавай пользователю технических вопросов.
- НЕ правь код — только спеки и obvious фиксы.
- Архитектурные расхождения → эскалация в `/architect`, не самостоятельное решение.
